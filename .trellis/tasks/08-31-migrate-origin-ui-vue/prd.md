# 迁移至 Origin UI Vue

## Goal

将 Safe House 前端从 Naive UI 迁移到 Origin UI Vue，并借此完成一次可感知的视觉更新。迁移后的界面优先采用 Origin UI Vue 的默认视觉语言与交互方式，不以复刻现有 Naive UI 外观为目标；在登录、授权、账号资料、子应用和管理配置等场景中，合理采用 Origin UI Vue Extended 的组合模式改善信息层级和操作体验。

## Background

- 当前项目是 Vue 3 + TypeScript + Vite 单页应用，组件层主要依赖 Naive UI。
- 现有界面覆盖首页、登录与注册、外部身份登录、账号资料、子应用、OIDC/OAuth 授权、外部身份与通知管理等流程。
- Origin UI Vue 是基于 Tailwind CSS、Reka UI 与 shadcn-vue 约定的源码复制/registry 模式，不是可直接替代 Naive UI 的单一运行时包。
- 当前 Naive UI 使用面覆盖 31 个 Vue 文件、50 种组件标签，并延伸至表单校验类型、消息/确认服务、自动导入和库内部样式选择器。
- 用户明确允许视觉风格随组件库更新，不要求迁移后还原当前样式。
- Safe House 的产品事实、中文语境、认证与授权行为、权限控制、运行时配置和现有业务能力需要保留。

## Requirements

### R1. 完整替换组件库

- 产品代码不再依赖 Naive UI 的运行时组件、组合式 API、表单类型、自动导入解析器或样式内部类名。
- Origin UI Vue 所需的基础设施、组件源码与依赖采用其官方推荐方式接入。
- 迁移后的本地 UI 组件应有清晰的目录边界和可维护的 typed props/emits 契约。

### R2. 可感知的视觉更新

- 所有主要页面和状态使用 Origin UI Vue 的默认组件语言，包括色彩、圆角、边框、排版、密度、焦点态与浮层表现。
- 不为保持 Naive UI 外观而建立大规模兼容 CSS 或旧主题复刻层。
- 保留 Safe House 的名称、中文内容和与身份入口相关的产品个性，但允许重写现有 `DESIGN.md` 中由 Naive UI 形成的视觉规则。

### R3. 场景级重组

- 不仅逐个替换原子组件，还要对高价值页面采用 Origin UI Vue Extended 或同源组合模式重新组织内容。
- 优先覆盖认证表单、用户资料、子应用列表与详情、密钥/凭据、授权确认、管理设置、空状态、错误状态和确认操作。
- 场景重组不得改变后端契约、权限语义或关键业务流程。

### R4. 行为与可访问性

- 登录、注册、授权、账户修改、外部身份、子应用与管理配置的现有行为保持可用。
- 表单保持可验证、可提交、可显示加载与错误状态；对话框、菜单、标签页、选择器和确认操作支持键盘与清晰焦点反馈。
- 桌面端与移动端均可用，至少覆盖项目现有的 768px 响应式边界及窄屏浮层。

### R5. 可控迁移

- 迁移过程按完整页面/流程分阶段执行，迁移中的代码允许 Origin 与 Naive UI 短期共存，但同一表单或对话框不得混用两套视觉系统。
- 最终阶段统一删除 Naive UI 依赖、配置与兼容代码。
- 每一阶段都应明确验证范围、回退点和跨阶段临时兼容边界。

## Acceptance Criteria

- [ ] AC1: `src/` 与构建配置中不存在 Naive UI 的组件标签、运行时 API、类型导入、解析器配置或针对 `.n-*` 内部类名的样式依赖。
- [ ] AC2: `package.json` 与锁文件不再声明 `naive-ui`；选定的 Origin 源码组件、官方要求的依赖和样式工具链已正确配置并记录来源。
- [ ] AC3: 首页、登录、注册、账号工作区、子应用、外部身份、管理配置、旧回调授权、新 OIDC 授权和外部登录回调均完成视觉迁移。
- [ ] AC4: 迁移后能够明显识别出 Origin UI Vue 的默认视觉语言，而非 Naive UI 外观的复刻。
- [ ] AC5: 至少在认证、授权、子应用/凭据、管理设置四类场景中采用 Extended 或同源组合模式完成信息层级优化。
- [ ] AC6: 所有原有权限门禁、加载/空/错误/成功状态和危险操作确认均保留。
- [ ] AC7: 键盘焦点、表单标签、对话框语义、图标按钮说明和移动端关键操作均通过人工检查。
- [ ] AC8: `pnpm type-check`、`pnpm lint` 与 `pnpm build` 通过；关键用户流程完成桌面和移动端人工回归。
- [ ] AC9: 项目组件规范与最终 `DESIGN.md` 已更新，不再把 Naive UI 约定描述为当前规范。

## Out of Scope

- 后端 API、数据模型、认证协议和权限模型的改造。
- 为迁移同时引入新的业务功能。
- 以像素级方式保留现有 Naive UI 视觉。
- 本次同时提供用户可切换的暗色主题；可以保留上游暗色 token，但不增加主题切换与持久化范围。
- 没有明确价值的动效、插画或营销型页面扩展。
